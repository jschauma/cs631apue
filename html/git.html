Using git(1)

Summary

Learning to use a code revision system and collaborating with others is an important aspect of programming. Git is a popular free and open source distributed version control system and well worth knowing at least the fundamental of.

Note: git(1) can be used without and independent of GitHub! In this class, we will use git(1) for your all of your coding assignments through our shared shell server.

See this video (from the CS615 class) for a quick introduction to using git without GitHub, just replace the linux-lab references with our hostname used here.

Your individual repository

Create a new repository for your CS631 code assignments by following these steps: 

$ ssh shell.cs631.dotwtf.wtf
shell$ mkdir .cs631.git
shell$ cd .cs631.git
shell$ git init --bare
Initialized empty Git repository in /home/jschauma/.cs631.git/
shell$ cd ..
shell$ git clone ~/.cs631.git cs631
Cloning into 'cs631'...
warning: You appear to have cloned an empty repository.
done.
shell$ cd cs631
shell$ vi README
shell$ git add README
shell$ git commit -m 'initialize CS631 repository'
 1 file changed, 1 insertion(+)
 create mode 100644 README
shell$ git push
Counting objects: 3, done.
Writing objects: 100% (3/3), 224 bytes | 0 bytes/s,
done.
Total 3 (delta 0), reused 0 (delta 0)
To /home/jschauma/.cs631.git
 * [new branch]      master -> master
shell$

Note: you now have a working directory in ~/cs631, and the bare git repository in ~/.cs631.git. You should never have a need to enter or access files in the bare git repository other than via the git(1) client.

Working with git

You should make it a habit to begin your working session by updating your copy of the repository and ending it by committing your changes. If you are ready to push your changes, you would then push them to the repository: 

$ cd group1
$ git pull
$ $EDITOR notes
[edit]
$ git commit
$ git push

Please always write a meaningful commit message. See these links for why/how:

  • Commit messages - Good practices
  • 5 Useful Tips For A Better Commit Message
  • A Note About Git Commit Messages
